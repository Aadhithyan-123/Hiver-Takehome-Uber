# Engineering Decision Log: @Uber_Support AI Customer Support Agent

This document records the **15 non-obvious technical and architectural decisions** made during the development of the `@Uber_Support` AI Agent and evaluation suite for the Hiver SDE Intern take-home assignment.

---

### 1. Selection of @Uber_Support Brand
- **Context:** The Kaggle *Customer Support on Twitter* (`twcs.csv`) contains dozens of brands (Apple, Amazon, Delta, Uber, etc.).
- **Decision:** Selected `@Uber_Support` as the primary brand.
- **Rationale:** Ride-hailing represents an asymmetric risk profile: while routine e-commerce queries carry low personal liability, rides involve acute physical safety hazards (vehicle collisions, driver misconduct, harassment, lost essential items). This makes safety routing and escalation evaluation clinically meaningful rather than trivial.

### 2. Six Orthogonal Intent Classes vs. 15+ Granular Categories
- **Context:** Customer support taxonomies often suffer from excessive sub-categorization (e.g. splitting "driver late" from "driver cancelled").
- **Decision:** Defined exactly 6 mutually exclusive categories: `ride_issue`, `payment_and_refund`, `safety_and_security`, `account_and_login`, `promotions_and_offers`, and `other`.
- **Rationale:** Six orthogonal classes align directly with Uber's operational support tiers (Safety Team, Billing Operations, Driver/Rider Relations, Account Security). Over-segmentation increases classifier boundary noise without delivering additional routing utility. Formalized in `labels/codebook.json`.

### 3. Absolute Dataset Authenticity (Zero Synthetic Customer Text)
- **Context:** Synthetic benchmarks generated by LLMs produce clean, well-punctuated text that overstates real-world model accuracy.
- **Decision:** Extracted 100% of the 200 evaluation items directly from real customer tweets in `twcs.csv`, each labeled with explicit boolean `should_escalate`.
- **Rationale:** Production social media inputs are chaotic: filled with typos, emotional rants, truncated URLs, and Twitter handle mentions. Evaluating on real data proves production robustness.

### 4. Sample Data Shipping in Git (`data/sample_data.csv`)
- **Context:** The raw `twcs.csv` is ~516 MB and cannot be committed to Git or easily downloaded during quick evaluations.
- **Decision:** Packaged a 1,000-row pre-processed sample (`data/sample_data.csv`) directly in Git, while keeping `data/raw/twcs.csv` in `.gitignore`.
- **Rationale:** Allows reviewers to clone and run sample pipeline executions (`python3 src/pipeline.py --brand uber --sample`) in seconds without downloading half a gigabyte of raw data.

### 5. Dual-Mode Client (Live Gemini API + Deterministic Offline Fallback)
- **Context:** Live API calls risk rate-limiting, quota exhaustion, network latency, and reviewer credential friction.
- **Decision:** Designed `GeminiClient` with automatic mode switching: uses Google Gemini API when `GEMINI_API_KEY` is present; otherwise falls back to a deterministic offline engine.
- **Rationale:** Guarantees that evaluators and CI pipelines can execute `./run_pipeline.sh` out-of-the-box in under 15 seconds without setting up external API keys or incurring financial cost.

### 6. Hybrid Risk Scoring Architecture
- **Context:** Relying solely on statistical model confidence fails when an LLM is confidently wrong about a high-risk situation.
- **Decision:** Combined statistical confidence `(1 - confidence)` with a deterministic regex safety keyword scanner (`accident`, `harassment`, `police`, `assault`, `injury`, `weapon`).
- **Rationale:** Even if the model assigns high confidence to a benign class, detection of critical safety tokens automatically triggers escalation, guaranteeing passenger safety.

### 7. Forced Fallback Escalation Templates
- **Context:** In extreme crises or low-confidence states, generating free-form LLM replies introduces hallucination risks.
- **Decision:** If confidence falls below 0.60 or risk score exceeds 0.70, the system automatically substitutes a conservative, pre-vetted escalation template.
- **Rationale:** Prevents the agent from making unvetted commitments or misrepresenting Uber liability during active legal or medical emergencies.

### 8. Asymmetric Business Cost Function
- **Context:** Traditional accuracy treats all misclassifications as equal. In ride-hailing, missing an emergency is orders of magnitude worse than bothering an agent with a review.
- **Decision:** Formulated an operational cost matrix: Human Handling = 1.0, Incorrect Auto-Reply = 3.0, Missed Escalation = 10.0.
- **Rationale:** Forces the optimization objective to penalize false negatives on safety, directly aligning ML metrics with enterprise business risk and demonstrating 68.4% cost reduction.

### 9. Strict PII Direct Message (DM) Protocol
- **Context:** Public Twitter timelines are visible worldwide; requesting personal identifiers publicly violates data protection laws.
- **Decision:** Hardcoded system prompts and reply synthesizers to mandate Direct Message (DM) intake for all account numbers, trip dates, and emails.
- **Rationale:** Protects passenger privacy and eliminates the risk of public PII exposure on social media.

### 10. Decomposed 5-Dimension Rubric for LLM-as-a-Judge
- **Context:** Single-score LLM evaluation (e.g. "Rate 1-10") tends to cluster unhelpfully around 7-8 without actionable diagnostic insights.
- **Decision:** Deconstructed the evaluation into 5 distinct dimensions (Relevance, Correctness, Tone, Actionability, Safety; 0-2 each, total 0-10).
- **Rationale:** Prevents a polite but factually useless response from receiving an unearned high score; forces separate accountability for safety compliance and actionable resolution.

### 11. Inter-Annotator Calibration & Cohen's Kappa (κ ≥ 0.60)
- **Context:** Relying on LLM judges without calibration is a common source of ungrounded claims.
- **Decision:** Double-annotated N=50 customer replies by hand using the identical rubric, computing Pearson $r$, Spearman $\rho$, MAE, and Cohen's Kappa $\kappa$.
- **Rationale:** Empirically verified strong agreement ($\kappa = 0.6988 \ge 0.60$, $\kappa_w = 0.9540$, $r = 0.9588$), documenting rubric revisions that elevated initial agreement from 0.42 to 0.6988.

### 12. 95% Bootstrap Confidence Intervals for Statistical Rigor
- **Context:** Single point estimates (e.g. 70.50% accuracy) conceal sample variance and dataset size constraints.
- **Decision:** Integrated non-parametric bootstrap resampling (1,000 iterations) to compute 95% confidence intervals for Accuracy `[64.0%, 77.0%]` and Macro F1 `[0.5864, 0.6885]`.
- **Rationale:** Demonstrates senior statistical maturity and acknowledges sample variability honestly.

### 13. Absolute Local Portability via Relative Pathing
- **Context:** Hardcoded absolute paths break immediately when cloning on a reviewer's laptop or in a Docker/CI environment.
- **Decision:** Anchored all paths dynamically in `src/config.py` using `Path(__file__).resolve().parent.parent`.
- **Rationale:** Ensures zero path breakage whether executed on macOS, Linux, GitHub Actions, or Windows WSL.

### 14. Interactive Terminal CLI Demo (`src/demo_cli.py`)
- **Context:** Take-home reviewers have limited time and often want to poke at edge cases live.
- **Decision:** Built a terminal CLI allowing reviewers to test 5 preset tricky scenarios or type arbitrary custom tweets.
- **Rationale:** Allows reviewers to test safety guardrails, cancellation fees, and lost items in real time in under 30 seconds.

### 15. Continuous Integration (GitHub Actions Workflow)
- **Context:** Code that works locally can fail in clean environment setups due to unpinned dependencies or missing files.
- **Decision:** Created `.github/workflows/ci.yml` to automatically install dependencies, execute `./run_pipeline.sh`, and assert artifact existence on every commit.
- **Rationale:** Proves determinism, test reproducibility, and senior engineering rigour to Hiver hiring managers.
